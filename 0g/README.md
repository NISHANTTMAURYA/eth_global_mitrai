# 0G Private Computer — main conversation flow

`src/lib/chat.ts` routes persona replies to 0G first when `OG_API_KEY` and `OG_MODEL` are configured. It sends the current character identity, bounded history and relevant approved memory, then returns the real provider and request ID to the chat API. The 0G response is used even when a model replies in plain prose instead of the requested JSON. The app no longer silently swaps that valid 0G answer for Vertex AI. Private conversation and the persistent mind remain in server-side Postgres.

Live local smoke check on 6 November 2026: a direct `reply()` call returned `provider: "0G"`, request ID `53a49445b222638a, 309bc687-39e1-4989-8e85-c11e38f9b147`, and two message bubbles. This is evidence of one 0G inference, not a claim that every production chat uses 0G. If its credentials are absent or its request fails, the app can use configured Vertex AI or labeled scripted rehearsal; actual provider is attached to replies.

The [Mumbai 0G Private Computer prize](https://ethglobal.com/events/mumbai/prizes#0g) asks for inference in the main user flow, request IDs, a working app judges can try, and why users return. Here the answer depends on accumulated personal context and a changing character over a fixed lifetime; remove inference and the main conversation stops being a responsive persona. A judge should perform a new owner conversation, inspect its `provider: "0G"` and request ID, then revisit the same character to see continuity. This is the target **Build with 0G Private Computer** track, not the physical AI hardware track.
